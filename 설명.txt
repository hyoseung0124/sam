일반 웹(MPA)과 SPA를 요청-응답 기준으로 비교하면 바로 이해됩니다.

비유:

일반 웹: 페이지를 이동할 때마다 새 책 한 권을 다시 받는 방식
SPA: 책은 한 번 받고, 안의 장면만 갈아끼우는 방식
비교:

첫 화면 접속
일반 웹: 서버가 완성된 HTML 페이지를 만들어서 내려줌
SPA: 서버는 껍데기 HTML + 자바스크립트 파일을 내려줌
메뉴 클릭(예: 사용자관리 → 로그조회)
일반 웹: 브라우저가 서버에 다시 요청, 서버가 새 HTML 생성, 페이지 전체 새로고침
SPA: 브라우저 안 자바스크립트가 화면만 바꿈, 보통 전체 새로고침 없음
서버 역할
일반 웹: 화면(HTML) 생성까지 서버가 담당
SPA: 서버는 주로 데이터 API 제공, 화면 렌더링은 브라우저가 담당
체감
일반 웹: 이동할 때 깜빡임/로딩이 상대적으로 큼
SPA: 앱처럼 부드럽고 빠르게 전환됨
네 프로젝트 관점
현재처럼 빌드 후 dist를 배포하는 구조는 SPA 배포 방식
즉, 화면 코드는 브라우저에서 동작하고 서버는 정적 파일 제공 + API 처리에 집중
핵심 한 줄:

일반 웹은 이동할 때마다 새 페이지를 서버가 만들어 주고,
SPA는 처음 받은 앱이 브라우저 안에서 계속 화면을 바꿔 주는 방식입니다.

$env:NODE_TLS_REJECT_UNAUTHORIZED="0"; vercel login
$env:NODE_TLS_REJECT_UNAUTHORIZED='0'; vercel --prod --yes
