키 유도 방식
입력한 마스터키를 바로 AES 키로 쓰지 않고, PBKDF2로 파생합니다.
반복 횟수 210000, 해시 SHA-256, 결과는 AES-GCM 256비트 키입니다.
구현: App.jsx:89-111
반복 횟수 상수: App.jsx:47
암호화 포맷
암호문 문자열은 항상 enc$ 접두어를 붙입니다.
내부 payload는 v, c, s, i, d 필드를 가집니다.
의미:
v: 버전
c: context (password 또는 storage)
s: salt (Base64)
i: iv (Base64)
d: ciphertext (Base64)
구현: App.jsx:113-134
복호화 방식
enc$ 확인 후 payload를 파싱하고,
같은 마스터키(+context)로 다시 PBKDF2 키를 만들어 AES-GCM 복호화합니다.
구현: App.jsx:136-152
레거시 호환(컨텍스트 없는 과거 데이터도 시도): App.jsx:154-169
비밀번호 필드 암호화
개별 접속정보 비밀번호는 context=password로 암호화됩니다.
저장 직전 암호화: App.jsx:992-1016
래퍼 함수: App.jsx:171-176, App.jsx:178-183
전체 저장소 암호화
items 배열 전체를 JSON 문자열로 만든 뒤 context=storage로 암호화해서 저장합니다.
저장 payload 생성: App.jsx:518-523
자동 저장(useEffect): App.jsx:678-710
로드 시 복호화 후 배열로 복원: App.jsx:530-557
왜 password와 storage를 분리하나
같은 마스터키라도 context를 다르게 넣어서 키 파생 입력이 달라집니다.
즉 password 데이터용 키와 storage 데이터용 키가 논리적으로 분리됩니다.
키 소스 생성 부분: App.jsx:116, App.jsx:148
한 줄 요약

마스터키 1개를 기반으로 PBKDF2 + AES-GCM을 사용하고, password/storage 컨텍스트를 분리해 암호화하는 구조입니다.


키 생성(PBKDF2) 단계에 넣는 랜덤 값
같은 마스터키라도 salt가 다르면 파생 키가 달라짐
목적: 사전공격/레인보우테이블 공격을 어렵게 만들기
IV (nonce)
AES-GCM 암호화 실행 시 넣는 랜덤 값
같은 키 + 같은 평문이라도 IV가 다르면 암호문이 달라짐
목적: 암호문 패턴 반복 방지, GCM 안전성 보장



저장된 값에서 c, s, i, d를 읽음
사용자가 입력한 마스터키 + c + s로 PBKDF2 키를 다시 만듦
그 키와 i로 d를 AES-GCM 복호화 시도
복호화가 성공하면 마스터키가 맞는 것
실패하면(인증 태그 검증 실패) 마스터키가 틀린 것


암호화: (마스터키:context) + 랜덤 salt + 고정 파라미터
복호화: (마스터키:context) + payload salt + 같은 고정 파라미터

저장소 데이터 (context=storage로 암호화)
└─ 마스터키 필요
   └─ items 배열 전체 복호화 가능
      └─ 각 항목의 개별 비밀번호 필드 (context=password로 암호화)
         └─ 마스터키 필요
            └─ 비밀번호 복호화 가능


1단계: 저장소 복호화 (마스터키 필요)
파일 읽음 → enc$ 확인 → context=storage 데이터 발견
→ 마스터키 + salt + context로 키 파생 (PBKDF2 210000회)
→ AES-GCM으로 items 배열 복호화 ✓

2단계: 개별 비밀번호 복호화 (마스터키 필요)
각 항목에서 password 필드 발견 → enc$ 확인 → context=password 데이터 발견
→ 마스터키 + salt + context로 키 파생 (PBKDF2 210000회)
→ AES-GCM으로 비밀번호 복호화 ✓
